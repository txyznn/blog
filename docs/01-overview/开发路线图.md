## UI 组件体系迁移

### 选型结论

保留 Next.js 作为应用框架，不更换为其他前端框架。当前问题主要来自页面样式和交互组件缺少统一规范，因此计划引入 **shadcn/ui** 作为组件体系。

shadcn/ui 适合当前项目的原因：

- 基于现有 Tailwind CSS，不需要重写整套样式技术栈
- 组件代码安装在项目内，方便按博客品牌进行修改
- 基于 Radix UI，具备较好的键盘操作、焦点管理和无障碍基础
- 适合统一按钮、导航、标签、表单、弹窗和主题变量
- 可以与 MDX 组件映射结合，扩展文章中的提示框、代码块和图片组件
